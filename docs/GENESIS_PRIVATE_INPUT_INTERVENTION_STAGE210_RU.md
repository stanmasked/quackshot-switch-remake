# QuackShot Remake — Stage210: приватный аудит вмешательства ввода

## Что измерено локально

Использован личный оригинальный ROM QuackShot и историческое
инструментированное ядро Genesis Plus GX, закреплённые SHA-256
в Stage203–204. Частные числовые отчёты сохранены вне GitHub.
Публичная ветка не содержит оригинального ROM, снимков кадров,
RAM/VRAM, BK2 или полных отчётов измерений.

Сравнены три прогона: `idle`, `right`, `right_repeat`, в двух
непересекающихся областях экрана:

- левая ROI: `[40, 120, 32, 60]`;
- правая ROI: `[123, 120, 32, 60]`.

В приватных результатах состояние игрока в RAM остаётся на
X=61 во время `idle`. При удержании RIGHT координата X
изменяется на всех контрольных кадрах. Синяя связная область
обнаруживается в левой ROI при `idle`, исчезает там при RIGHT
и появляется в правой ROI; при повторном RIGHT все числовые
строки точно совпадают. RAM X/Y, camera и render-buffer
совпадают между двумя отчётами ROI.

Это свидетельствует о воспроизводимой связи экранной цветовой
области с управляющим воздействием, но **не доказывает**, что
область принадлежит именно Дональду или соответствует хитбоксу,
точке опоры ног либо физике оригинальной игры.

## Новый инструмент

`tools/genesis_private_input_intervention_audit.py` проверяет
только два локальных приватных JSON. Сначала он проверяет SHA-pinned
архив исследовательского ядра, затем читает каждый отчёт через
Stage208 `read_private_report` (абсолютный путь, отдельный от
репозитория и архива, обычный файл, права не шире `0600`,
максимум 128 KiB).

Проверяются:
- строгая схема и фиксированные две ROI;
- пять контрольных кадров и закреплённые числовые координаты RAM, камеры и буфера прокрутки;
- наличие/отсутствие цветовой группы в соответствующей ROI для
  `idle` и `RIGHT`;
- границы и центроид цветовой группы без сохранения пикселей;
- совпадение RAM/camera/render-buffer в обеих ROI;
- точное совпадение всех строк `RIGHT` и `RIGHT-repeat`;
- отказ при лишних полях, ошибочных SHA-метках или попытках
  заявить подтверждённую личность объекта/хитбокс.

Команда для уже имеющихся приватных отчётов:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tools/genesis_private_input_intervention_audit.py \
  --bundle "/private/rom-free-emulator" \
  --left "/private-results/left-stage210.json" \
  --right "/private-results/right-stage210.json"
```

При успехе печатается только
`GENESIS_STAGE210_PRIVATE_INPUT_INTERVENTION_PASS_NOT_IDENTITY_ATTESTED`.
Ошибка выдаёт общий текст без измерений и локальных путей.

## Проверка частных отчётов

В пользовательском архиве Stage209–210 сверены размеры и SHA-256 всех
шести числовых JSON по вложенному манифесту. Два отчёта Stage210 затем
были прочитаны из временных файлов с правами `0600` и вне Git-checkout.
Офлайн-аудитор из успешного ROM-free CI-артефакта прошёл проверку
комплекта и вернул `GENESIS_STAGE210_PRIVATE_INPUT_INTERVENTION_PASS_NOT_IDENTITY_ATTESTED`.

В текущей ревизии дополнительно закреплены известные значения камеры и
буфера прокрутки для пяти контрольных кадров. Эти поля совпали в обоих
отчётах с опубликованными числовыми опорными значениями; новый CI проверяет
отказ при их согласованной подмене. Сам ROM не запускался GitHub Actions,
а архив не содержит оригинальную игру или видеоданные.

## Ограничения и CI

Офлайн-аудит проверяет только внутреннюю согласованность сохранённых
чисел. Он не перезапускает ROM и не предоставляет независимую
криптографическую аттестацию процесса. Поэтому `safe_to_modify_switch_physics`
и `original_hitbox_or_contact_plane_verified` остаются `false`.

Добавлены 15 полностью синтетических ROM-free тестов. Валидатор
включён в транзитивный набор инструментов Stage203 и проверку импорта
собранного архива в GitHub Actions. Игровая физика и Switch NRO
не меняются.
