# QuackShot Remake — этап №66: очередь GitHub Actions по актуальному коммиту

## Почему потребовалась доработка

После частых небольших коммитов в Draft PR №2 прежние версии
`Portable gameplay core`, `Nintendo Switch NRO (prototype)`
и `NeXium Switch Emulator Runtime` накапливались в очереди
GitHub Actions. Это затрудняло проверку **актуального HEAD**
и требовало вручную отделять полезные свежие результаты
от промежуточных запусков.

## Исправление

Во всех трёх workflow теперь задана верхнеуровневая политика:

```yaml
concurrency:
  group: quackshot-${{ github.workflow }}-${{ github.event.pull_request.number || github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}
```

При новом коммите **в том же PR** GitHub отменяет старые
ожидающие или выполняющиеся запуски **этого же workflow**,
предпочитая актуальную ревизию. Никакой пользовательский
ROM или ресурс QuackShot для этого не нужен.

Название workflow является частью группы, поэтому проверки
C/GCC/Clang/SDL2, Nintendo Switch NRO и NeXium **не мешают
друг другу**. Номер PR разделяет разные запросы изменений.
При push непосредственно в `main` принудительная отмена
отключена, чтобы не терять журнал проверок основной ветки.

Важно: эта настройка **не увеличивает квоту runner**,
не гарантирует мгновенный запуск и не подтверждает
корректность тестов. Отменённый устаревший workflow
нельзя трактовать как успешный или проваленный: нужно
смотреть **именно итоговый workflow актуального коммита**.

## Защита от регрессий

В `tests/test_ci_concurrency.py` добавлены четыре проверки:
наличие политики во всех трёх файлах, верхнеуровневое
расположение, уникальность названий workflow и отсутствие
безусловной отмены push-проверок. Они выполняются
`python3 -m unittest discover -s tests -p 'test_ci_concurrency.py' -v`
в основной CI-матрице до сборки C.

Оригинальные файлы игры в публичный репозиторий не добавляются.
