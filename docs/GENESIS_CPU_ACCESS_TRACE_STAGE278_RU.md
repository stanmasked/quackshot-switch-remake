# QuackShot Remake — Stage278: ограниченная трассировка чтений и записей CPU

**Статус:** подготовлена отдельная ветка; интеграционный CI ещё не запускался. Не считать этап принятым до прохождения проверок.

## Цель

Трассировка Stage219–277 регистрировала выбранные записи Work RAM и отдельные точки исполнения 68000. Это показывало, где состояние меняется, но не всегда позволяло установить, какие значения программа читает перед переходом между состояниями. Stage278 добавляет числовые события чтения для четырёх небольших адресных интервалов, сохраняя прежнюю трассировку записей и снимки VDP/объектов.

## Контракт данных

- Запись: сохраняются кадр, PC инструкции, адрес CPU, смещение Work RAM, ширина, значение и метка `access_kind = "W"`.
- Чтение: те же числовые поля, `access_kind = "R"` и `access_value`; поле `write_value` для чтений отсутствует.
- Новая схема: `quackshot_private_m68k_cpu_access_trace_v2`.
- Существующий список адресов записи сохранён без расширения.
- Отдельный список чтений ограничен диапазонами `0x8F94–0x8F99`, `0xA2C8–0xA2CD`, `0xA2E4–0xA2E7` и `0xEE56–0xEE59` (конец диапазона не включается).
- Окно ограничено 128 кадрами; ёмкость буфера событий — 65 536, переполнение отражается статусом.
- При несовместимом или неизвестном типе доступа сборщик завершается ошибкой, а не угадывает смысл события.

## Синтетическая проверка CI

Workflow создаёт искусственный ROM-образ без игровых ресурсов. Программа записывает `0x1234` в `0xFFA2E6`, затем читает то же слово. Проверка должна подтвердить две записи в журнале в правильном порядке: запись с PC `0x206`, затем чтение с PC `0x20E`; оба значения равны `0x1234`. Для чтения запрещено поле `write_value`. Параллельно сохраняются прежние проверки PC/A0/CCR и числовых записей VDP SAT.

## Границы доказательства

Это исследование наблюдаемости, а не восстановление игрового поведения. Синтетический тест проверяет контракт инструмента, но не доказывает, что выбранные адреса соответствуют логике оригинального QuackShot. Никакие оригинальные ROM, дампы RAM/VRAM, байты инструкций, кадры, аудио или извлечённые игровые ресурсы в отчёт не включаются. Результаты реального исследования, если оно будет выполнено, должны оставаться в закрытом хранилище с контрольными суммами.

## Приёмка

1. Genesis libretro core workflow проходит на точном head.
2. Python unit-тесты подтверждают разделение чтений и записей и отклонение неизвестного типа события.
3. Синтетический запуск подтверждает две ожидаемые записи и нулевое переполнение.
4. После CI фиксируются точный SHA коммита, сводка workflow и контрольные суммы артефактов; оригинальные материалы остаются приватными.
