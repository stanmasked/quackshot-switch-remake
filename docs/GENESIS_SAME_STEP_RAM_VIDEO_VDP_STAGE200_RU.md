# QuackShot Remake — Stage200: три числовых источника на одном шаге libretro

## Почему понадобился этот этап

Ранее мы по отдельности получили:
- числовые координаты `X/Y` персонажа из рабочей RAM оригинального
  Genesis QuackShot;
- статистику синего оттенка пикселей из локального буфера libretro;
- аппаратные значения HScroll Plane A и B из инструментированного
  Genesis Plus GX.

Stage199 выявил между ранее сохранёнными цветовым центром и
расчётной экранной координатой неодинаковое смещение на двух кадрах.
Склеивать несинхронизированные исследования и объявлять результат
границей оригинального хитбокса **недопустимо**.

## Новый приватный пробник

`tools/genesis_city_same_step_triplet_probe.py` выполняет три
**независимых** прохождения того же первого CITY: idle, RIGHT,
RIGHT-repeat. ROM и инструментированная сборка Genesis Plus GX
проверяются SHA-256 **до и после каждого запуска**.

В каждом прохождении анализируются кадры
`2180, 2220, 2280, 2297, 2350`.

На одном **индексе шага libretro** программа собирает:

1. Из RAM — `world_x`, `world_y`, программное состояние камеры
   `0x8524`, буфер прокрутки `0x852C`.
2. Из **текущего видеокадра в памяти**, только в выбранном ROI —
   количество синих пикселей, их центроид X/Y и рамку. Пиксели никуда
   не записываются.
3. Из внутреннего аппаратного состояния VDP — четыре числовые записи
   HScroll по линиям `0, 64, 128, 192` через существующий
   исследовательский hook
   `quackshot_research_vdp_hscroll`.

Выполняются уже закреплённые исходными числовыми свидетельствами
проверки положения героя по пяти контрольным кадрам, 450 считываний
RIGHT сверх idle, одинакового повторного RIGHT, корректности HScroll
Plane A/B и флагов режима VDP.

Используется **отдельная инструментированная**, фиксированная по хешу
сборка Genesis Plus GX, а не стандартная из Stage198:

```text
ROM: 30581220f6c914709853828811fe143e283896189a64eedf1444dc908b5cac34
Instrumented core: 4e3381cf5bfa7ff387bbe6887e7e31453bf4c8c85b295aa66d6d07d415dde7aa
```

## Ограничение фаз

<escape>video callback</escape> вызывается **внутри**
`retro_run(frame)`. RAM и аппаратный VDP снимаются **после**
возвращения того же `retro_run(frame)`, перед следующей подачей
управления.

Поэтому «один кадр» в этом отчёте — только **общий счётчик вызова
libretro**. Это НЕ независимая аттестация фаз 68000, DMA, VBlank,
растрового вывода, применения скролла к конкретному пикселю или момента
физического контакта.

## Публичный числовой контракт

Приватный `quackshot_private_genesis_ram_video_vdp_same_step_v1`
экспортирует по пяти шагам лишь RAM X/Y, скролл, количество цветных
пикселей и цветовой центроид. Полные VDP scanlines и RGB-кадры
остаются временными значениями процесса, никогда не записываются в
выходной JSON.

Неподтверждённые выводы закреплены явными флагами:

```json
{
  "same_cpu_vdp_scanout_phase_verified": false,
  "original_collision_hitbox_or_contact_plane_verified": false,
  "safe_to_modify_switch_physics": false
}
```

Отчёт не помещается в публичную ветку. Запись допускается только
в новый абсолютный `.json` файл вне репозитория, с правами `0600`,
без замены уже существующего файла и без вывода приватных путей.

## Команда для будущей локальной проверки

```sh
python3 tools/genesis_city_same_step_triplet_probe.py \
  --rom "/private/QuackShot Starring Donald Duck.gen" \
  --core "/private/genesis_plus_gx_instrumented_libretro.so" \
  --roi 100 80 85 140 \
  --output "/private/quackshot-triplet-stage200.json"
```

**Эта команда не запускалась в Stage200**: исходный ROM и
инструментированная сборка не загружались в публичный GitHub.

## ROM-free регрессии

```sh
python3 -m unittest discover -s tests \
  -p 'test_genesis_city_same_step_triplet_probe.py' -v
```

Тестовые данные полностью синтетические. Проверяются пять маркеров,
два идентичных RIGHT-прогона, искажение видео и RAM, нарушение одной
из четырёх аппаратных строк VDP, некорректная выборка кадров,
инъекция недопустимых исходных данных, невалидная фаза, а также
эксклюзивная приватная запись.

## Дальнейшее действие

В следующем приватном эксперименте нужно подтвердить исходное
сопоставление видеокадра и end-of-frame VDP **на едином захвате**,
после чего отдельным причинным коллизионным тестом определить
контактную плоскость. До этого изменение физики и хитбокса Switch
по результату центрирования синего цвета запрещено.
