# Этап №17 — числовая переменная прокрутки и направление камеры Mega Drive

18 октября 2026. Все наблюдения получены на **приватном**
пользовательском ROM QuackShot Starring Donald Duck (524288 байт),
SHA-256:
30581220f6c914709853828811fe143e283896189a64eedf1444dc908b5cac34.

Исходный ROM, видеокадры, игровой код, звук и содержимое RAM
не выгружались в GitHub. Для исследования использовано локальное
Genesis Plus GX libretro v1.7.4.

## Результат: отдельное состояние камеры в рабочей RAM

Прежняя гипотеза об «экранной координате» по адресу 0x8F58
оказалась недостаточной: в правом прогоне этот адрес меняется
с 281 до 482, то есть выходит далеко за ширину экрана Mega Drive.
Он соответствует объектно/спрайтовой структуре **в мировых
координатах**, а не непосредственно экранному X.

Новый анализ **всех 64 КиБ RAM** выделил другое поле:
- **0x8524** — сильный кандидат на текущую горизонтальную позицию
  прокрутки/камеры игрового движка (16-битное поле, little-endian
  представление в конкретной RAM-структуре);
- **0xFEC6** — почти совпадающее поле, но оно НЕ является точной
  покадровой копией: в нескольких кадрах содержимое различается;
- **0x852C** — ещё одно связанное поле со сдвигом порядка 1–2
  пикселей во время движения, возможно промежуточный буфер.

**Эти адреса RAM не являются доказанными аппаратными регистрами
VDP.** Чтобы установить точную связь, требуется наблюдать
непосредственные записи команд HScroll в VDP и экранный вывод.

## Вправо: появление и предел слежения

Прогон оригинальной городской локации с удержанием RIGHT:
- Кадр 2123: мировая X = 141, 0x8524 = 0.
- **Кадр 2124:** мировая X = 142, 0x8524 = 1 —
  первое наблюдаемое смещение камеры.
- Кадр 2180: мировая X = 233, scroll = 92.
- Кадр 2220: мировая X = 298, scroll = 157.
- Кадр 2300: мировая X = 428, scroll = 287.
- Кадр 2400: мировая X = 498, scroll = 358.

В кадрах 2180–2344 разность **world X − scroll находится
между 140 и 142**. Когда удерживаемый RIGHT приводит Дональда
к стене и X перестаёт меняться, значение камеры фиксируется
на 358 и тоже больше не растёт.

Это значительно сильнее прежнего предположения о пиксельном
якоре 134: 134 было центром *отфильтрованных цветных пикселей
спрайта*, а не реальной точкой привязки игровой камеры.

## Влево: подтверждённая зона нечувствительности

Если после упора в стену начать LEFT с кадра 2360:

| Кадр | Мир X | 0x8524 |
| --- | ---: | ---: |
| 2360 | 498 | 358 |
| 2374 | 481 | 358 |
| **2375** | **480** | **357** |
| 2380 | 472 | 349 |
| 2390 | 455 | 333 |
| 2400 | 439 | 317 |
| 2430 | 397 | 273 |

Камера **не сразу следует назад**: герой сперва проходит
внутри экрана, и лишь на кадре 2375 прокрутка начинает
уменьшаться. После этого разница X − scroll на кадрах
2380–2430 остаётся **122–124 пикселя**.

Следовательно, разумная приближённая модель имеет
**два порога слежения** — примерно 141 при движении вправо
и 123 при движении влево, а не постоянный якорь.

На отдельном прыжковом прогоне, сохраняя RIGHT, разность
X − scroll также находится в диапазоне 140–142 на
кадрах 2310–2350.

## Важная аномалия зеркального адреса

В прогонах RIGHT, повторе RIGHT и RIGHT→LEFT поле 0xFEC6
расходится с 0x8524 на кадрах **2203, 2281**.
В прогоне RIGHT с прыжком добавляется кадр **2393**.

Поэтому копировать 0xFEC6 и объявлять его
«точной аппаратной прокруткой» недопустимо. Возможны
переходный буфер, другое соглашение о счёте или
промежуточная операция, но это пока гипотезы.

## Проверка воспроизводимости

Оригинальный ROM локально исполнялся в **5 независимых
прогонах по 2550 кадров**:

1. Без действий после общего запуска.
2. RIGHT [2070,2520).
3. Точный повтор RIGHT с тем же начальным состоянием.
4. RIGHT [2070,2360), затем LEFT [2360,2430).
5. RIGHT [2070,2510) плюс прыжок A [2310,2350).

Для каждого прогона записано **382 числовых наблюдения
на кадрах 2069–2450**, всего 1910 RAM-отсчётов.
Два RIGHT-прогона совпали во всех числовых полях и
контрольных CRC32 выходного видео.

Инструмент: tools/genesis_camera_state_probe.py.
Независимые искусственные тесты:
tests/test_genesis_camera_state_probe.py.

Пример локального запуска без загрузки игрового ROM в GitHub:

    python3 tools/genesis_camera_state_probe.py \
      --core /private/genesis_plus_gx_libretro.so \
      --rom "/private/QuackShot Starring Donald Duck.gen" \
      --expected-sha256 30581220f6c914709853828811fe143e283896189a64eedf1444dc908b5cac34 \
      --output /tmp/quackshot-camera-numeric.json

Числовое свидетельство:
research/observations/user_rom_camera_state_2026-10-18.json.

## Значение для Switch-ремейка

Экспериментальный профиль на тестовой сцене CITY теперь может
использовать два проверенных числовых порога (141/123)
вместо прежнего предварительного 134. Это приближение,
так как сам Switch-полигон имеет другое игровое пространство
и собственные тайлы/коллизии.

Обычный профиль прототипа, остальные локации,
раскладка кнопок и оригинальные ресурсы остаются неизменными.

Следующий уровень точности — получить **записи фактических
VDP HScroll-команд** оригинальной Mega Drive, проверить дробные
интервалы прокрутки, перенос экранной позиции игрока и граничные
поведения камеры на разных сценах.
