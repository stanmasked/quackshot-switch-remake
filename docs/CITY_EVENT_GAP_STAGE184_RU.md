# QuackShot Remake — Stage184: отчёт о расхождениях событий с оригиналом

## Цель

Stage183 проверил, что одинаковый маршрут при переносе начала отсчёта оставляет прежними интервалы и позиции событий. Stage184 использует эту идею для **числового сравнения с ранее опубликованными измерениями оригинального первого города**, не утверждая, что искусственная карта Nintendo Switch совпадает с оригиналом.

Новый инструмент `tools/city_event_gap.py` **не запускает оригинальную ROM**, не читает BK2 и не получает приватные изображения. Он выполняет уже существующий ROM-free тест `qs_city_landmark_timeline_tests` и сопоставляет его маркер с опубликованными числовыми записями:

- `research/observations/user_rom_fixedpoint_motion_2026-10-18.json`
- `research/observations/user_rom_city_obstacles_2026-10-18.json`
- `research/observations/user_rom_camera_state_2026-10-18.json`

Повторно используется `reference_evidence_integrity.validate()`, проверяющий происхождение наблюдений, согласованность источников и активные константы модели. Маркер отвергается, если он дублирован, повреждён или содержащиеся в нём сравнения противоречат исходным числовым записям.

## Два вида расхождений

Данные исходной игры из ранее опубликованных наблюдений:

| Событие | Кадр оригинала | От кадра ввода 2070 |
|---|---:|---:|
| Начало падения | 2281 | 211 |
| Нижний пол | 2297 | 227 |
| Остановка у стены | 2344 | 274 |

Исходные **интервалы**: падение → приземление = 16 кадров, приземление → стена = 47 кадров, падение → стена = 63 кадра. Для обратной прокрутки кандидата RAM отсчёт начинается с LEFT на кадре 2360, движение камеры зафиксировано на кадре 2375 (15 кадров); координаты героя через 30 и 70 кадров разворота равны 455 и 397.

Stage184 рассчитывает два раздельных отчёта:

1. **Сырые отклонения:** разность каждого времени синтетического маршрута и относительного времени оригинала.
2. **Отклонения после однократного выравнивания начала падения:** сдвиг вычисляется **только по первому падению**. Для нижнего пола и стены сохраняются независимые остаточные ошибки; для межсобытийных интервалов пересчитывается физически осмысленная разность длительности.

Таким образом, одинаковое смещение всех трёх событий не ошибочно выдаётся за три проблемы физики. А изменение разницы между падением и приземлением остаётся видимым даже после временного выравнивания.

Также публикуются **диагностические** расхождения задержки обратной камеры и X через 30/70 кадров. Числовой кандидат RAM прокрутки `0x8524` не называется восстановленным регистром VDP.

## Автоматическая проверка

В workflow `Portable gameplay core` после CTest добавлена отдельная стадия:

- шесть Python-тестов проверяют расчёт, отказ при поддельных/несогласованных метках и связность публичных числовых источников;
- после сборки исполняется настоящий синтетический бинарный тест, создаётся `city-event-gap.json`;
- отчёт прикладывается к каждому из четырёх GCC/Clang Debug/Release артефактов;
- сравнение матрицы дополнительно проверяет, что **целочисленные событийные отпечатки** совпали во всех четырёх сборках (места возможных дробных отличий в X не подменяют эту проверку).

CLI:

```sh
cmake -S . -B build -DQS_BUILD_DESKTOP=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
python3 -m unittest discover -s tests -p 'test_city_event_gap.py' -v
python3 tools/city_event_gap.py --binary build/qs_city_landmark_timeline_tests --out city-event-gap.json
```

**Ограничение:** исходная карта, точные хитбоксы, абсолютная шкала кадров и оригинальная камера не восстановлены; итоговый JSON имеет статус `DIAGNOSTIC_ONLY_NOT_ROM_PARITY`. Даже нулевые разности не доказывают тождественность оригиналу. Не публикуются ROM, BK2, сырые RAM-дампы, оригинальные кадры, музыка или спрайты.
