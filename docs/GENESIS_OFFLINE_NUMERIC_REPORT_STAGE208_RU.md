# QuackShot Remake — Stage208: независимая офлайн-проверка приватных числовых отчётов

## Цель

Stage204/207 позволяют запустить оригинальный QuackShot в локальной
исследовательской среде и сохранить **только числовые** результаты.
После такого запуска нужен способ отдельно проверить готовый файл,
**не открывая повторно оригинальный ROM** и не запуская эмулятор.

Новый `tools/genesis_offline_numeric_report_audit.py` проверяет
локальный JSON: его структуру, контрольные кадры, значения и
расчётную согласованность. Результат *не* подтверждает происхождение
цифр от реальной эмуляции: пользователь может подменить JSON.
Сертификат подлинности оригинального процесса не создаётся.

## Команда локальной проверки

После распаковки подтверждённого набора
`genesis-plus-gx-rom-free-linux-x64` на совместимой системе:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tools/genesis_offline_numeric_report_audit.py \
  --bundle "/private/rom-free-emulator" \
  --report "/private/numeric-results/quackshot-triplet.json"
```

Команда запускается только с существующим отчётом пользователя,
размещённым вне публичного Git-репозитория и вне комплекта. Она
проверяет доступный исторический бинарник и SHA всех комплектных
файлов через `preflight`, затем читает **не более 128 KiB**
приватного JSON с правами доступа `0600`.
Возможные символьные ссылки и чрезмерно большие файлы отвергаются.

В stdout печатается только:

```text
GENESIS_STAGE208_NUMERIC_REPORT_SCHEMA_PASS_NOT_ORIGIN_ATTESTED
```

Либо без приватных путей или чисел:

```text
GENESIS_STAGE208_NUMERIC_REPORT_REJECTED
```

Никакие оригинальные игровые файлы в публичный GitHub не передаются.

## Что проверяется

Принимаются два уже определённых формата:

- `quackshot_private_genesis_ram_video_vdp_same_step_v1`:
  Stage200, в том числе факультативный отчёт Stage205/207 с
  четырёхсвязными цветовыми компонентами;
- `quackshot_genesis_video_hscroll_same_step_bracket_v1`:
  Stage201, сравнение HScroll во время видео callback и после
  `retro_run`.

Для обоих форматов проверяются зафиксированные SHA-256 оригинального
ROM и инструментированного Genesis Plus GX, строго пять индексов
`2180, 2220, 2280, 2297, 2350`, оригинальные известные
целочисленные позиции X/Y и связь
`candidate_screen_x = world_x + Plane_A_HScroll`.
Цветовой центроид и X-смещение проверяются с точностью до тысячной
доли пикселя. При нулевом числе пикселей координаты должны
отсутствовать. Все поля и их типы проверяются по белому списку.

Для Stage201 проверяются восемь числовых разностей HScroll по
четырём строкам и двум плоскостям, а также общий флаг изменения.
Для Stage207 проверяются числовые размеры, координаты и поля
кандидатов. Любые дополнительные поля, включая RAW RGB/RAM/VRAM,
отклоняются.

## Чего не доказывает успех

Проверка содержимого **не доказывает**, что исходный ROM действительно
запущен именно в этот момент, что реальный VDP был в конкретной
фазе CPU/scanout или что синий объект — Дональд. Она не определяет
коллизионный прямоугольник, точку опоры ног или характеристики
физики оригинальной игры.

Поэтому при любом принятом отчёте:
- `local_provenance_independently_attested=false`;
- `original_hitbox_verified=false`;
- `safe_to_modify_switch_physics=false`.

## CI

Новый валидатор и его 11 ROM-free тестов включены в
`.github/workflows/genesis-libretro-core.yml`. Исследовательский
архив Stage203 дополнен аудитором и его транзитивными Python
зависимостями; после сборки проверяются импорт из архива и
целостность SHA. Искусственные тесты не читают ROM.

Nintendo Switch NRO, C99 физика, графика и контент игры не меняются.
