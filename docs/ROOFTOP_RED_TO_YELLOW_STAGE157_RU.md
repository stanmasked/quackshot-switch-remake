# QuackShot Remake — Stage157: настоящий переход от красного к жёлтому выстрелу

После полностью подтверждённого Stage156 новый тест NeXium проверяет не только блокировку жёлтого переключателя красными снарядами, но и его **реальное открытие жёлтым снарядом после смены оружия**.

## Реальный маршрут гостевого контроллера

1. В CITY TEST получить красное оружие прыжком.
2. Войти в ROOFTOP и выстрелить красным: 0/6 клеток моста.
3. Выйти через START на карту и повторно войти кнопкой Nintendo A.
4. Выстрелить красным второй раз: мост остаётся 0/6.
5. Нажать физическую Nintendo X (в текущей закреплённой NeXium-раскладке это клавиша V), чтобы сменить красное оружие на жёлтое.
6. Выстрелить кнопкой Nintendo Y (клавиша Z); подлинный жёлтый снаряд должен открыть ровно 6/6 клеток моста, которые остаются открытыми.

## Источники доказательства

Прежние гостевые CSV NRO `quackshot-red-acquire.csv`, `quackshot-rooftop-guest.csv`, `quackshot-rooftop-transitions.csv` остаются неизменными. Новый отдельный `quackshot-rooftop-weapon.csv` синхронно записывает только наблюдаемые значения `input.change`, `weapon_before`, `weapon_after`, `red_unlocked` с реального кадра после `qs_step`. Он не изменяет игровое состояние. Каждый `seq` и `frame` обязан точно совпасть с основным NRO-журналом ROOFTOP.

Анализатор сначала подтверждает **всю** цепочку Stage156 на кадрах до смены оружия, затем требует ровно один настоящий переход RED→YELLOW, один новый FIRE, непрерывный жёлтый снаряд и изменение шести физических клеток моста только при попадании в переключатель. По меньшей мере 30 следующих кадров должны удерживать мост открытым. Все сообщения внешнего контроллера сверяются с номерами кадров гостевых файлов.

Две независимые сессии обязаны использовать одинаковую контрольную сумму NRO и закреплённый архив NeXium. Негативные Python-проверки отвергают повторную смену, фиктивное нажатие, поддельный жёлтый цвет, преждевременное открытие, повреждённые кадры и неправильные события хоста.

## Выполнение

```bash
python3 -m unittest discover -s tests -p test_rooftop_red_to_yellow.py
cmake -S . -B build-stage157 -DQS_BUILD_DESKTOP=OFF
cmake --build build-stage157 --parallel 2
ctest --test-dir build-stage157 --output-on-failure -R rooftop_red_to_yellow_guest_trace_protocol
```

Полное испытание двух настоящих гостевых маршрутов запускается через `.github/workflows/nexium-rooftop-red-to-yellow.yml`.
