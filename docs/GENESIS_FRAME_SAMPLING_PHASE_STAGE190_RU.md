# QuackShot Remake — Stage190: фаза выборки RAM относительно libretro-кадра

## Вывод из чтения исходного кода

В собственной обвязке `tools/genesis_libretro_probe.py` выполнение одного шага имеет следующий порядок:

1. Устанавливается номер наблюдаемого кадра `state["frame"] = frame`.
2. В callback ввода назначаются кнопки сценария именно для этого `frame`.
3. Вызывается `core.retro_run()`; видеоколбэк срабатывает **внутри** вызова.
4. **После возврата из `retro_run()`**, через `retro_get_memory_data` читается системная RAM и вызывается `checkpoint_sink(frame, ram)`.
5. Только затем цикл переходит к следующему `frame` и новому вводу.

Следовательно, метки Stage188 `2280`, `2281`, `2297` относятся к **post-retro_run** состоянию с ярлыком соответствующей итерации цикла, а не к состоянию *перед* выполнением `retro_run` для этого номера кадра.

**Но это не устанавливает порядок инструкций оригинального CPU 68000, момент обновления VDP и точный сканлайн изображения.** Эти вопросы остаются открытыми; название кадра — контракт нашей обвязки, а не доказательство аппаратной фазы оригинала.

## Исправления проекта

- `run_core()` добавляет в возвращаемые числовые метаданные два обязательных поля:
  `ram_checkpoint_phase="post_retro_run_before_next_input"` и `video_callback_phase="during_retro_run"`.
- Приватный пробник Stage188 **отклоняет** полученные данные, если используемая обвязка не подтверждает оба контракта, и только при успешном запуске включает их в итоговый небольшой числовой отчёт. Это не делает исходный ROM публичным.
- Анализатор Stage189 требует те же поля, чтобы не принимать данные с другим способом метки кадров. Неизвестные поля и сырые дампы по-прежнему отклоняются.

## ROM-free подтверждение

Добавлен `tests/test_genesis_checkpoint_phase_contract.py` с полностью вымышленным `FakeLibretroCore`. Он не загружает игру и не вызывает настоящий Genesis Plus GX. В RAM-подобном синтетическом массиве из 64 KiB записывается только номер шага и флаг виртуального RIGHT. На каждом шаге независимый `checkpoint_sink` обязан увидеть:

| Индекс цикла | Синтетическое значение состояния после шага | Ввод RIGHT |
|---:|---:|---|
| 0 | 1 | Нет |
| 1 | 2 | Да |
| 2 | 3 | Да |
| 3 | 4 | Нет |

В этом тесте проверяется фактический порядок callback вызовов: `retro_run` завершён **до** чтения RAM; чтение RAM завершено **до** `checkpoint_sink`. Тест также подтверждает 4 видеоколбэка, очистку core и отказ Stage188 при несовместимой фазе.

Дополнительно unit-тест Stage189 проверяет, что посторонняя или подложная строка фазы измерения не пройдёт валидацию.

## Итог и ограничения

Этап исправляет документирование **уже существовавшей** фазы получения измерений, но не исправляет и не переопределяет целые кадры оригинального прохождения. Физика C99/Switch NRO и созданные нами тестовые карты не меняются. Оригинальный ROM, BK2, RAM-дампы, исходные спрайты, музыка и кадры видео не публикуются. Нового реального оригинального прогона этим изменением не выполнялось.

После подтверждения CI следующий обоснованный шаг — запустить Stage188 в доверенной локальной среде с ROM, проверить метки через Stage189 и только тогда решать вопрос о калибровке прыжка.
