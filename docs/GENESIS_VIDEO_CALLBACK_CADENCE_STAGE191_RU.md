# QuackShot Remake — Stage191: проверка видеоколбэков внутри каждого retro_run

## Мотивация

Stage190 подтвердил порядок установки ввода, выполнения `retro_run` и
чтения RAM **в собственной обвязке**. Но равенство
`frames_video_callbacks == TOTAL` не доказывает, что каждый вызов
`retro_run` дал ровно один видеоколбэк. Например, 0 на кадре N и 2
на кадре N+1 сохраняют общую сумму, а локальное соответствие фаз уже
не гарантировано.

## Реализация

`tools/genesis_libretro_probe.py` агрегирует только три числовых счётчика:

- `frames_without_video_callback`: шаги без видеоколбэка;
- `frames_with_multiple_video_callbacks`: шаги с двумя или более;
- `video_callbacks_outside_retro_run`: вызовы вне активного шага.

Ни покадровая серия, ни содержимое видеобуфера, ни дамп RAM этим
изменением не записываются. `retro_run` заключён в `try/finally`,
чтобы даже при исключении не оставался ложный флаг активного кадра.

`tools/genesis_city_fractional_fall_probe.py` теперь требует ноль
для всех трёх счётчиков, дополнительно к общей сумме и маркерам фазы,
**до** анализа трёх приватных прогонов. Это fail-closed контракт именно
исследовательского измерения Stage188; общая обвязка может описать
некорректную последовательность, не объявляя её пригодной для
оригинального временного сопоставления.

## ROM-free тесты

Расширен `tests/test_genesis_checkpoint_phase_contract.py`:

1. Нормальный FakeLibretroCore: один видеоколбэк на шаг.
2. Пропуск одного и удвоение следующего: сумма остаётся правильной,
   но два новых счётчика выявляют нарушение.
3. Видеоколбэк во время `retro_load_game` отслеживается отдельно.
4. Приватный Stage188 отказывается принимать оба варианта, даже если
   подложенный отчёт заявляет корректную фазу.

Тест использует только искусственные данные. Никакой оригинальный ROM
не запускается и не публикуется.

## Граница доказанного

Этот контракт выявляет некорректную кратность libretro callback-вызовов,
но **не** доказывает, какой именно инструкцией Motorola 68000 или
сканлайном VDP создано изображение. Не следует переносить фазовую
метку на оригинальную аппаратную синхронизацию или менять физику
Switch на основании одного факта совпадения количества callback.

Следующая содержательная калибровка требует приватного прогона с
закреплёнными SHA-256 исходного ROM и Genesis Plus GX и последующей
проверки небольшого числового отчёта средствами Stage189.
