# QuackShot Remake — Stage229: числовая трассировка профилей столкновения

## Цель

Автоматизировать проверку пересечения игрового прямоугольника игрока с профилями двух объектов в RAM, не выгружая сырые данные оригинальной игры. Дополнительно трасса PC/A0 фиксирует числовой адрес возврата из стека только в одной инструкции, которая выставляет глобальное событие EE09.

## Что добавлено

- `--collision-profile-snapshot-frames` — до 24 кадров для выборочных снимков объектов `0xFF9000` и `0xFF9040`.
- Для каждого объекта выводятся только числовые поля: тип, под-состояние, координаты, указатель анимации, индекс профиля, четыре декодированных signed-offset значения, рассчитанный прямоугольник и пересечение с игровым прямоугольником игрока из `0x8F54`.
- Профиль берётся из таблицы `0x7E500`; в отчёт попадают только декодированные смещения, не исходные байты таблицы.
- PC-trace schema v3 дополнительно содержит SP и числовой longword на вершине стека только для PC `0x00B866`. Это позволяет сопоставить событие с вызывающей процедурой без экспорта стековых байтов.
- Диагностика ограничена выбранными адресами и кадрами; переполнение трассы явно отражается в статусе.

## Результат приватного локального прогона

На базовом кадре 2353 объект-пул слот `0xFF9000` имеет тип 3, под-состояние 1, мировые координаты `(528,176)` и профиль `0x3D`. Его смещения декодируются как `Ymin=-40`, `Ymax=+40`, `Xmin=-10`, `Xmax=+20`, поэтому прямоугольник объекта равен X `[518,548]`, Y `[136,216]`.

Игровой прямоугольник игрока в этот кадр: X `[497,521]`, Y `[118,161]`. Пересечение X `[518,521]`, Y `[136,161]`. В тот же кадр PC `0x00B866` записывает `0xFF` в `0xFFEE09` при `A0=0xFF9000`; стековый возврат равен `0x009644`, что соответствует возврату из диспетчера объектов после `JSR (A1)`.

В контрольном A+RIGHT-маршруте на кадре 2353 прямоугольник игрока X `[489,513]`, Y `[165,208]` не пересекается с объектом типа 3; запись `EE09` и событие PC `0x00B866` отсутствуют. Второй объект `0xFF9040` использует профиль `0x40`, смещения `[-6,+4,-2,+4]`, и также не пересекается с прямоугольником игрока в проверенном окне.

Это подтверждает срабатывание собственного прямоугольного теста столкновения игры в базовом сценарии. Название/игровая идентичность объекта типа 3 ещё не установлены; переносить эти координаты в физику Switch до независимого теста не следует.

## Синтетические проверки

Локальная сборка закреплённого Genesis Plus GX с новым стековым полем прошла синтетический тест: программа делает две ожидаемые записи, PC-trace фиксирует `PC=0x00B866`, `A0=0xFFA300`, `SP=0xFFFEFC`, return PC `0x00000214`. Отдельный тест профилей подтверждает пересечение для профиля `0x3D` и отсутствие пересечения для профиля `0x40`.

Официальный CI этого Draft PR должен повторить проверку на синтетическом ROM до того, как инструмент будет использоваться как утверждённая сборка.

## Приватность

В репозитории и CI не включаются оригинальный или модифицированный ROM, сырые RAM/VRAM, сырые слова SAT, байты инструкций, пиксели кадров, графика, аудио или полные приватные трассы. Сырые значения существуют только в локальном сеансе анализа и не записываются в публичные артефакты.
