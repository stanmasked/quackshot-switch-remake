# QuackShot Remake — Stage226–227: каталог анимации и прямая трассировка выбора

**Статус:** структура каталога и прямой индексный доступ через +0x04 подтверждены; точное соответствие каждой SAT-позе ещё не доказано.  
**Изменения физики Switch:** нет.

## 1. Воспроизводимость

- Оригинальный ROM проверен локально по SHA-256: **30581220f6c914709853828811fe143e283896189a64eedf1444dc908b5cac34**.
- Диагностическое ядро Genesis Plus GX: SHA-256 **ff1b07af59613794acb103042b28164cb77c3a79b5df1f6a5b03ae2b534f5a9d**.
- Повторены три сценария с проверенной последовательностью входа в первый городской уровень: покой, удержание RIGHT на кадрах [2070, 2160) и удержание A на кадрах [2310, 2350).
- Каждый сценарий завершил 2600 кадров и 2600 видеовызовов.
- Дополнительно сняты по 128 числовых SAT/объектных наблюдений на сценарий: кадры [2050, 2178) для покоя и движения вправо, [2280, 2408) для прыжка. Итого 384 выбранных кадра.
- RAM и SAT снимались после retro_run; видеовызовы происходят внутри retro_run. Это фиксирует фазу наблюдения, но не утверждает точный порядок исполнения 68000-инструкций внутри кадра.

ROM, сырые RAM/VRAM/SAT-байты, инструкции, изображения кадров, звук и полные частные трассы в репозиторий не включались.

## 2. Исправление предыдущей интерпретации таблицы

Указатель объекта +0x20 остаётся **0x00021372** во всех выбранных кадрах. Предыдущая версия Stage225 выделяла первые 16 смещений, но это только начальный монотонный участок каталога.

Первое значение по адресу 0x21372 равно 0x0054. Оно задаёт начало области данных после 84-байтового каталога, то есть **42 двухбайтовых записи смещений**, а не 16. Все 42 значения различны, выровнены по слову и указывают внутрь ROM. Порядок важен: после первых 16 возрастающих значений каталог содержит смещения не по порядку.

Смещения в исходном порядке:

    0054 0082 00B0 00BE 00CC 00E0 00F4 00F8 00FC 0102 0108 0116 0124 0132 0140 0148
    0156 0150 015C 0168 0174 017E 0188 0190 0198 01A2 0058 0086 01C0 01CA 01D4 01DE
    01F4 01FA 01E8 01EE 01AC 01B6 0200 0216 0224 0228

В первых 16 позициях прослеживаются такие числовые формы записей:

| Индексы каталога | Заголовок-слово | Число следующих 16-битных значений |
|---|---:|---:|
| 0–1 | 0x00FF | 22 у каждой |
| 2–3 | 0x05FF | 6 у каждой |
| 4–5 | 0x03FF | 9 у каждой |
| 6–7 | 0x0004 | 1 у каждой |
| 8–9 | 0x0104 | 2 у каждой |
| 10–11 | 0x0504 | 6 у каждой |
| 12–13 | 0x0500 | 6 у каждой |
| 14–15 | 0x0204 | 3 у каждой |

Это структурные наблюдения; назначение полей заголовка пока не расшифровано. Повторяющаяся парная форма совместима с вариантами одного набора, но сама по себе не доказывает зеркальное направление.

Два поздних элемента каталога — индекс 26 со смещением 0x0058 и индекс 27 со смещением 0x0086 — указывают **внутрь** первых двух длинных записей, а не на их начало. Следовательно, каталог нельзя трактовать как 42 независимых однотипных дескриптора. Это также объясняет, почему простой подсчёт первых 16 адресов давал неполную картину.

## 3. Stage227 — прямой путь выбора записи

Статическая декодировка 68000-кода возле ROM-offset 0x9A26 разрешила главное сомнение Stage225/226:

1. Код загружает базовый указатель из поля объекта +0x20.
2. Читает слово +0x04, умножает его на два и использует как смещение внутри каталога.
3. Берёт 16-битное относительное смещение из каталога и прибавляет его к базовому указателю.
4. Затем читает первые два байта выбранной записи; второй байт участвует в обновлении поля +0x09.

Это подтверждает, что **+0x04 — индекс каталога**, а не только общий код состояния. Наблюдаемые значения сопоставляются так:

| Сценарий/состояние | +0x04 | Индекс каталога | Относительное смещение | Цель |
|---|---:|---:|---:|---|
| Покой | 27 | 27 | 0x0086 | внутренняя ссылка на слово 0x1308 внутри длинной записи с началом 0x0082 |
| Движение вправо | 3 | 3 | 0x00BE | заголовок 0x05FF, далее 6 слов |
| Прыжок | 5 | 5 | 0x00E0 | заголовок 0x03FF, далее 9 слов |
| Поздний переход после прыжка | 1 | 1 | 0x0082 | заголовок 0x00FF, далее 22 слова |

В покое индекс 27 выбирает смещение 0x0086, которое находится внутри блока с началом 0x0082; это реальная внутренняя ссылка. Именно поэтому предположение о каталоге только из первых 16 записей было недостаточным.

### Уточнение роли +0x24

Первоначальная гипотеза Stage226 о +0x24 как прямом индексе каталога **отвергнута** после трассировки записи в RAM. Инструкции по ROM-offsets 0x9AD6 и 0x9ADA записывают два последовательных байта из текущего потока анимации в поля объекта +0x24 и +0x25. Значения 1, 9 и 11 коррелируют с несколькими сменами SAT-сигнатуры, но это выходные данные потока анимации, а не подтверждённый индекс каталога.

Это важная коррекция: прямой выбор каталожной записи делает +0x04; +0x24/+0x25 принадлежат последующей обработке анимационных данных. Значение самих байтов +0x24/+0x25 ещё предстоит расшифровать.

Дополнительная CPU write-трасса на кадрах 2280–2407 завершилась без переполнения: 5263 события записи и 11530 событий выбранных PC. Она показывает, что +0x24/+0x25 записываются в каждом выбранном кадре инструкциями по ROM-offsets 0x9AD6/0x9ADA. Поля +0x26 и +0x28 декрементируются отдельными участками кода возле 0x6540 и 0x6500 в коротком переходе после приземления; их точное назначение пока не установлено.

## 4. Сопоставление с SAT

- Семейство с pattern_index в диапазоне 1920–1960 присутствовало во всех 384 выбранных кадрах.
- Кластер 1024/1026/1042/1045 не встретился ни в одном из этих снимков. Прежнее назначение этого кластера игроку остаётся отвергнутым для проверенных сценариев.
- Сигнатура семейства около 1920 меняется во время подъёма, возле вершины прыжка и в переходе после приземления. Это согласуется с обработкой потока анимации, но точное соответствие каждой записи конкретной SAT-позе ещё не установлено.

Примеры числовых сигнатур:

- кадр 2312: 1920, 1923, 1939, 1943, 1946;
- кадр 2335: 1920, 1923, 1935, 1936;
- кадр 2343: 1920, 1923, 1935, 1938;
- кадр 2372: 1920, 1922, 1925;
- кадр 2385: 1920, 1923, 1927, 1930.

Список pattern ID — числовое резюме декодированных SAT-атрибутов, не сырые SAT-слова или VRAM.

## 5. Проверки

- Локальный аудит оригинального ROM прошёл: 42 записи каталога, 42 уникальных смещения, все цели в пределах ROM.
- Восемь синтетических unit-тестов парсера прошли. Тесты не используют ROM и проверяют границы, выравнивание, сохранение порядка и обнаружение внутренних ссылок.
- В существующем Stage225 CI запуск сборки ROM-free ядра завершился успешно; остальные проверки той ревизии не считаются подтверждёнными, пока GitHub Actions не завершит их.
- Игровая физика Nintendo Switch не изменялась.

## Следующий шаг — Stage228

Расшифровать, как выбранный блок управляет продвижением потока анимации: установить точную роль заголовков, +0x06, +0x08/+0x09 и байтов +0x24/+0x25; отдельно проверить обработку маркера 0xFF и внутренних ссылок 0x0058/0x0086. Затем сопоставить конкретные записи с последовательностями SAT. До этого физику не менять.
