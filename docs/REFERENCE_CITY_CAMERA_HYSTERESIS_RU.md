# Этап №17 — камера с разными порогами слежения

Исследование выполнено на приватном пользовательском QuackShot ROM
с SHA-256 30581220f6c914709853828811fe143e283896189a64eedf1444dc908b5cac34.
Ни байты ROM, ни оригинальные изображения, RAM-дампы и звуки не
добавлены в Nintendo Switch-ремейк.

## Почему изменён прежний якорь 134

В этапе №16 предварительная настройка камеры использовала
экранную X≈134, найденную по усреднённым **голубым пикселям
спрайта** в двух локальных оригинальных скриншотах.

Это не было наблюдением состояния регистра VDP. Новые
покадровые наблюдения 64 КиБ RAM оригинала выявили
числовое поле по адресу **0x8524**, которое ведёт себя
как горизонтальное состояние камеры:

- первый правый сдвиг камеры — **кадр 2124**, при мировой X=142;
- при движении вправо X героя − значение 0x8524 находится
  между **140 и 142**;
- на стене при мировой X=498 камера фиксируется на 358;
- после разворота влево камера не начинает двигаться сразу:
  первый сдвиг влево — **кадр 2375**;
- в устойчивом обратном движении разность X − 0x8524
  находится между **122 и 124**.

Эти факты подтверждены **пятью независимыми исходными
запусками Genesis Plus GX**, каждый по 2550 кадров.
Два одинаковых RIGHT-прогона полностью совпали численно и
по контрольным видеохешам.

Адреса 0xFEC6 и 0x852C тоже связаны с прокруткой,
но их значения не следует считать эквивалентными 0x8524:
0xFEC6 имеет редкие однокадровые расхождения.
Настоящий аппаратный VDP HScroll ещё не прочитан напрямую.

## Новая экспериментальная камера Switch

При входе в CITY TEST с **R+A** используется двумерный
коридор по экранному X героя:

    screen_x = hero_world_x - camera_x
    if screen_x > 141: camera_x = hero_world_x - 141
    if screen_x < 123: camera_x = hero_world_x - 123
    camera_x = clamp(camera_x, 0, test_stage_width - viewport_width)

Таким образом, вблизи стены камера останавливается и
при смене RIGHT на LEFT даёт герою сначала отойти назад,
прежде чем начать обратное слежение.

**Обычный профиль** сохраняет прежнюю формулу:

    camera_x = clamp(hero_world_x - 150, 0, max_camera_x)

Эти формулы не утверждают тождество оригинальному коду.
В оригинальной Mega Drive отличается разрешение,
присутствуют специфические атрибуты спрайтов и возможная
построчная горизонтальная прокрутка VDP. Два числовых
порога — воспроизводимая аппроксимация только
первой наблюдавшейся городской локации.

## Защита от регрессий

В tests/test_reference_city_obstacle.c расширен набор
самостоятельных искусственных проверок:

- при движении вправо на синтетическом полигоне
  экранная X остаётся около 141;
- при развороте камера сначала сохраняет прежнюю X,
  пока персонаж проходит около 12 шагов в обратном направлении;
- после пересечения порога X камеры уменьшается,
  а экранная X удерживается около 123;
- нормальный профиль по-прежнему ориентируется на 150;
- тайловые столкновения, прыжок и повторные прогоны
  сохраняют детерминизм.

Исследовательские адреса RAM не читаются самим NRO:
он использует только числовые пороги, записанные в нашем
собственном игровом коде.

## Следующее исследование

Найти фактические команды горизонтальной прокрутки VDP
(обычный HScroll / построчная таблица) и сопоставить их
покадрово с 0x8524, чтобы отделить программную позицию камеры
от реального воздействия на видеопроцессор. Затем исследовать
края уровня и реакцию камеры на прыжок/падение.
