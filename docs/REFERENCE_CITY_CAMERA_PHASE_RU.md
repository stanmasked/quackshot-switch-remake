# QuackShot Remake — этап №20: отдельная камера отрисовки

Исследовательские результаты первого городского уровня Mega Drive
показывают, что программная камера (числовое поле RAM 0x8524)
и отрисованный горизонтальный сдвиг VDP, соответствующий
буферу RAM 0x852C, могут отличаться на переходных кадрах.

Примеры из приватных числовых наблюдений (не изображения):

| Кадр | Камера 0x8524 | VDP-буфер 0x852C |
| --- | ---: | ---: |
| 2180 | 92 | 90 |
| 2220 | 157 | 155 |
| 2375 | 357 | 358 |
| 2380 | 349 | 351 |
| 2400 | 358 | 358 |

Источник — PR №1, \`research/observations/user_rom_vdp_hscroll_2026-10-18.json\`
и \`docs/GENESIS_VDP_HSCROLL_PARALLAX_RU.md\`.

## Новая экспериментальная модель

Только при R+A в CITY TEST:

- \`camera_x\`: текущая игровая позиция камеры. Пороги
  слежения 141/123 **не изменены**.
- \`render_camera_x\`: снимок \`camera_x\` перед последним
  обновлением симуляции, то есть **задержка на один шаг 60 Гц**.
- SDL-рендер использует \`render_camera_x\` для героя, мира
  и двух декоративных слоёв; дальний слой всё так же
  движется как \`floor(render_camera_x / 2)\`.
- Обычный профиль использует прежнюю текущую \`camera_x\`,
  без задержки. Обе камеры сбрасываются на входе в сцену.

Это **инженерная гипотеза**, согласующаяся с несколькими
выборками оригинала. Одного кадра недостаточно, чтобы
считать расписание операций VDP оригинала восстановленным:
например, порядок VBlank/DMA и дробные интервалы ещё
не измерены и не воспроизведены.

## Фактические проверки

\`tests/test_camera_phase.c\` независимо проверяет
задержку текущего игрового шага, правое и левое движение,
отсутствие задержки в обычном профиле и сброс при
переходе между сценами.

Гостевой NRO на каждом пятнадцатом шаге CITY TEST
создаёт два **связанных по номеру кадра** CSV-события:

- \`QS_TRACE_CAMERA_PHASE = 13\`: старшие 16 бит —
  текущая камера, младшие 16 бит — камера отрисовки.
- \`QS_TRACE_PARALLAX = 12\`: старшие 16 бит —
  отрисованная ближняя плоскость, младшие — дальняя.

Проверка NeXium отклоняет архив, если эти пары не
совпадают по кадру и порядок событий неверен, если
отрисованная плоскость не совпадает с отрисованной
камерой, либо если не доказано положительное и
отрицательное отклонение камеры при реальном движении.
Это проверка **исполнения нашего NRO**, не измерение
точности оригинального кода.

Исходный ROM, содержимое оригинальной RAM/VRAM,
спрайты, музыка и уровни в публичный репозиторий и
бинарный NRO не добавляются.
