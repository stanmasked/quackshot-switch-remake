# QuackShot Remake — этап №88: гостевая диагностика полного маршрута

Технический NRO для Nintendo Switch теперь создаёт отдельный CSV
`sdmc:/switch/quackshot-route.csv`, содержащий контрольные события
детерминированного прохождения синтетической сцены CITY TEST.

Это **внутренний автотест** внутри гостевого процесса, а не запись
реальных нажатий Joy-Con. Автотест использует настоящие функции `qs_step`
и `QsInput`; игровая сессия, которую видит пользователь, не меняется.

События: SPAWN, CHECKPOINT, CRATE_FIRE, CRATE_BROKEN, SPRING,
HEART, LEDGE, CLEAR, REENTRY. Строки содержат числовой тик,
координаты в тысячных долях пикселя, таймер и источник
`qs_step_simulated_inputs`.

Рабочий процесс NeXium извлекает CSV из эмулируемой SD и проверяет
его отдельным `tools/verify_guest_route.py`. Успех требует полного
порядка событий, правдоподобных мировых координат, зачёта финиша и
корректного повторного входа. Гостевой файл нельзя заменить данными,
созданными только на CI-хосте.

Независимая проверка реального контроллера (R+A, B, направление, Y,
Plus) и движения остаётся в прежнем `quackshot-motion.csv`.
Она **не доказывает**, что весь уровень пройден физическими
нажатиями в NeXium. Для этого потребуется отдельный тест.
