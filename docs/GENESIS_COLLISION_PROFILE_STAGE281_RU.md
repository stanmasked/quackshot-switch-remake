# QuackShot Stage281 — ограниченные числовые профили столкновений

Перенесена только числовая модель прямоугольников столкновений из старого экспериментального PR №79. Новая ветка основана на уже проверенном Stage280. Устаревшие интерфейсы CPU trace, SP и данные объектов не перезаписываются.

Необязательный аргумент `--collision-profile-snapshot-frames` запрашивает не более 24 кадров. В закрытом сеансе читаются два фиксированных объектных слота Work RAM (`0xFF9000` и `0xFF9040`) и четыре знаковых смещения из таблицы `0x7E500`. На выходе — только числовые признаки профиля, вычисленные границы и пересечение с прямоугольником игрока, без сырых байтов исходной RAM/ROM, графики или аудио.

Синтетический тест проверяет профиль `0x3D` с пересечением и `0x40` без пересечения. Отдельно тестируются неверные размеры входа, испорченные прямоугольники, ограничение кадров и явные признаки отсутствия приватных ресурсов в JSON.

Геометрия пока не доказана для прочих сцен; индексы объектов не означают установленную идентичность игровых персонажей. Реальная коллизия должна подтверждаться независимыми записями оригинального движка, прежде чем переносить эти результаты в физику Switch.

Оригинальные игровые ресурсы и подробные трассы хранятся только в приватном Google Drive. Публичный GitHub содержит лишь код и искусственные числовые тесты.
