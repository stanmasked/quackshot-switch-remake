# Этап №22 — количественная проверка задержки камеры оригинала

Установлено по числовым наблюдениям пользовательского Mega Drive ROM:
RAM 0x8524 хранит программное состояние камеры, а RAM 0x852C
совпадает с реальным аппаратным VDP HScroll плоскости A по модулю.
Например, в кадре 2180 получены 92/90, в кадре 2380 — 349/351.

**Разница в 1–2 пикселя не доказывает задержку в 1–2 кадра.**
Доказательство точного времени обновления оригинальной камеры
ещё отсутствует. В Switch-прототипе задержка в один игровой шаг
остаётся явно помеченной инженерной гипотезой.

## Реализованное измерение

Инструмент \`tools/genesis_camera_phase_model.py\` встроен в приватную
команду \`tools/genesis_vdp_scroll_probe.py\`. На тех же 382 плотных
кадрах пяти исходных прогонов после проверки аппаратного VDP он
сопоставляет пять кандидатов задержки: 0, 1, 2, 3 и 4 кадра.

Общая формула абсолютной ошибки:

    |RAM_0x852C[frame] - RAM_0x8524[frame - candidate_lag]|

Для объективного сравнения все кандидаты используют одинаковые кадры
**с реальным перемещением игровой камеры**. Исследуются отдельно
прямое слежение, начало разворота, устойчивый обратный ход и
прыжок с удержанием направления.

В результат включены только суммарные ошибки, число совпадений,
размер набора, число совпадений с точностью до 1 px, минимумы
(включая ничьи) и строгий критерий однокадровой гипотезы.
**Полная покадровая история, ROM, RAM, кадры изображения, музыка
и VRAM не экспортируются.**

Недостающий соседний кадр и недостоверные данные приводят к отказу.
В GitHub Actions проверяются синтетические задержки 0–4,
повреждение данных, отсутствие движения и выпадение кадра.

## Состояние

Исследовательский инструмент и тесты доступны без приватного ROM.
Пока пользовательский ROM не будет повторно исполнен локально,
результат реального сравнения задержек **неизвестен**.
Даже лучший кандидат отражает корреляцию end-of-frame снимков,
но не доказательство точного времени инструкций 68000, DMA или VBlank.

В Nintendo Switch NRO/геймплей на этом этапе изменений нет.
