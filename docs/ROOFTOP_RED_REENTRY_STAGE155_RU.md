# QuackShot Remake — Stage155: сохранение красного оружия при повторном входе

## Цель

После полностью подтверждённого Stage154 следующий отдельный регрессионный сценарий проверяет игровое ядро C99 **без эмулятора**:

1. Вход в авторскую тестовую сцену ROOFTOP из карты с ранее полученным красным оружием.
2. Красный выстрел не включает жёлтый переключатель: мост остаётся 0/6.
3. Реальный переход через `qs_step(QsInput.back)` на карту и повторный выбор ROOFTOP через `qs_step(QsInput.select)` сохраняет разблокированное красное оружие.
4. Второй красный выстрел тоже не активирует мост, а обычный жёлтый затем по-прежнему может его включить.
5. После нового выхода и входа мост снова сброшен, а разблокировка красного оружия не теряется и CITY TEST не выдаёт повторную награду.
6. Удержание BACK 45 кадров не создаёт лишнего входа и не сбрасывает прогресс.

## Границы проверки

Это **нативные C99 тесты правил переходов и коллизий**, а не новые самостоятельные NeXium-запуски или доказательство реального повторного красного выстрела в эмуляторе. Фикстура начинается с уже заработанной разблокировки красного оружия; **подлинное получение** красного пикапа и подлинный красный выстрел были отдельно подтверждены двумя гостевыми сеансами Stage154 (коммит `2032dd3d`, [CI №39471809672](https://github.com/stanmasked/quackshot-switch-remake/actions/runs/39471809672)).

Тест не изменяет игровую физику. Для изоляции проверки положения перед выстрелом герой ставится в тестовое положение x640, соответствующее существующей `test_rooftop_shot_bridge.c`; игровое взаимодействие выстрела происходит через `qs_step`. Это не является гостевой телеметрией.

## Запуск

```bash
cmake -S . -B build-stage155 -DQS_BUILD_DESKTOP=OFF
cmake --build build-stage155 --parallel 2
ctest --test-dir build-stage155 --output-on-failure -R rooftop_red_reentry_native
```

Ветки Stage153/Stage154 и оригинальный образ Mega Drive оставлены неизменными. Никаких оригинальных ресурсов QuackShot в этом тесте нет.
