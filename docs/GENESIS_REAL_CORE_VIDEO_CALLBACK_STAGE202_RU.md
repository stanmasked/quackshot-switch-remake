# QuackShot Remake — Stage202: настоящий VDP hook, синтетический ROM

## Зачем нужен этап

В Stage201 была проверена согласованность VDP и видеокадра при помощи
**искусственного Python-libretro ядра**. Сборка настоящего Genesis Plus GX
успешно проходила отдельно, однако ни одно испытание на настоящем бинарнике
не проверяло вызов `quackshot_research_vdp_hscroll` **из самого video callback**.

Stage202 закрывает этот пробел без использования оригинальной игры:
в GitHub Actions инструментированное ядро исполняет только самостоятельно
составленный бесконечный цикл Motorola 68000 с командами `60 FE`.
Этот тестовый .gen не является оригинальным QuackShot.

## Добавленный исполняемый тест

`tools/ci_genesis_vdp_video_callback_smoke.py`:

1. Сначала сверяет размер 128 KiB, заголовок **OPENAI TEST ONLY NO GAME
   ASSETS** и точную инструкцию цикла. Другие ROM-файлы отвергаются
   **до загрузки** в эмулятор.
2. Загружает настоящий ROM-free-скомпилированный Genesis Plus GX с
   read-only `quackshot_research_vdp_hscroll`.
3. Во время двух независимых запусков по 90 шагов проверяет, что
   callback видео вызывает VDP hook на шагах `0, 1, 30, 60, 89`,
   а RAM-снимок берётся после тех же `retro_run`.
4. Считывает только 8 целочисленных величин HScroll: по Plane A/B
   на линиях 0, 64, 128 и 192; также сверяет маленькую область
   RGB-кадра и количество кадровых callback.
5. Проверяет порядок `video callback → возврат retro_run → RAM checkpoint`
   и совпадение двух независимых результатов (видео CRC, числовые ROI и VDP).
6. Выводит только `GENESIS_STAGE202_REAL_CORE_VDP_CALLBACK_SYNTHETIC_PASS`
   либо обезличенный код ошибки — **ни кадры, ни RAM, ни VRAM**.

Это **не** доказательство того, что эксперимент с оригинальным
QuackShot даст те же фазы или идентифицирует хитбокс.

## Проверки безопасности

Шесть ROM-free unit-тестов отказывают при чужих заголовках ROM,
ошибке кода синтетического цикла, несовпадающем повторном прогоне
и проверяют корректность вызовов четырёх строк аппаратного VDP.

Реальное испытание запускается в существующем
`.github/workflows/genesis-libretro-core.yml` **до удаления**
`ci-only-synthetic.gen`. По завершении файл удаляется; оригинальные
игровые ресурсы в workflow отсутствуют.

## Исправление комплектации архива

Раньше архив собранного исследовательского ядра включал
`genesis_libretro_probe.py`, но **не включал** его зависимость
`genesis_blue_roi_numeric.py` (введена Stage198).
В Stage202 эта зависимость добавлена и выполняется импортный
smoke-тест непосредственно из каталога формируемого архива.

Архив предназначен для использования ядра и базовых пробников.
Большие Stage200/201 исследования используют полный рабочий
репозиторий с числовыми reference-файлами и не объявляются
автономными программами из одного пакета.

## Граница проверки

- Исходный ROM QuackShot, BK2, графика, музыка, сырая RAM и VRAM
  **не включаются** в публичную сборку и пакет.
- `safe_to_modify_switch_physics` остаётся **false** для
  исследований оригинальной геометрии.
- Ни `qs_game.c`, ни NRO, ни графика Switch не изменены.

Слияние выполняется только после успешных GitHub Actions. Для
внутренней проверки сначала применяются реальные ROM-free-артефакты
CI, а не предположения о реальном исполнении Genesis.
