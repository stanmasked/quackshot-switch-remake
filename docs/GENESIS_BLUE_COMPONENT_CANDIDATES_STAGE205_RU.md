# QuackShot Remake — Stage205: связные цветовые области без утверждений о хитбоксе

## Зачем

В архивных числовых наблюдениях Genesis фигурирует средний X
всех синих пикселей фиксированного прямоугольника. Stage199 показал,
что такой центроид не даёт постоянного смещения относительно VDP
на двух кадрах. Причина не доказана: область может содержать фоновые
пиксели, элементы анимации и несколько несвязанных объектов.

Stage205 дополняет этот прежний, крайне простой фильтр
**разделением пикселей на связные компоненты**. Это отдельные
цветовые *кандидаты*, а не идентификация Дональда, ROM-спрайтов или
контакта ног с поверхностью.

## Что измеряется

`tools/genesis_blue_roi_components.py` поддерживает три формата
libretro: `0RGB1555`, `XRGB8888`, `RGB565`.

Порог синего тот же, что в Stage198: компоненты R/G/B приводятся
к пяти битам, отмечаются пиксели с `B >= 19`,
`B-R >= 8`, `B-G >= 4`. Дальше используется **4-связность**:
соседство только по горизонтали или вертикали, диагонали сами по
себе не соединяются.

Для небольшого выбранного ROI (не более 65 536 пикселей) алгоритм
выделяет области, отсеивает компоненты с числом пикселей меньше 5
и возвращает максимум четыре самых крупных кандидата.

Каждый кандидат содержит только:
- целое число синих пикселей;
- X/Y центроид в тысячных долях пикселя;
- прямоугольник границ;
- флаг касания границы исходного ROI.

Есть также количество всех областей и флаг численного преобладания
крупнейшей над второй по площади (минимум вдвое). Даже при одном
«доминирующем» кандидате поле
`selected_component_is_proven_player=false`.

Маска пикселей, исходные framebuffer, VRAM, графические листы,
сырой ROM, звук или спрайт в отчёт **не записываются**.

## Приватные исследовательские команды

В пробник Stage198 добавлен необязательный флаг:

```sh
python3 tools/genesis_city_visual_roi_probe.py \
  --core "/private/genesis_plus_gx_original_libretro.so" \
  --rom "/private/QuackShot Starring Donald Duck.gen" \
  --roi 100 80 85 140 \
  --component-candidates \
  --output "/private/numbers-blue-components-stage205.json"
```

Для **инструментированного** ядра, используемого в исследовательском
комплекте Stage203/204, тот же числовой анализ доступен в Stage200:

```sh
python3 tools/genesis_city_same_step_triplet_probe.py \
  --core "/private/genesis_plus_gx_instrumented_libretro.so" \
  --rom "/private/QuackShot Starring Donald Duck.gen" \
  --roi 100 80 85 140 \
  --component-candidates \
  --output "/private/numbers-triplet-blue-stage205.json"
```

Оба инструмента сохраняют старое поведение **без флага**. При его
включении три независимых запуска проверяют совпадение числовых
кандидатов двух RIGHT-прогонов, согласованность количества синих
пикселей с исходной статистикой и точную разрешённую схему вывода.

Выход по-прежнему приватный, с правами 0600 и без перезаписи.
Исходный ROM не загружается в GitHub и **не запускался в Stage205**.

## Автоматические тесты

`tests/test_genesis_blue_roi_components.py`,
`tests/test_genesis_blue_roi_components_witness.py`,
`tests/test_genesis_blue_roi_components_triplet.py` проверяют
фальшивые изображения, три пиксельных формата, четырёхсвязность,
смешанные пятна и фон, границы области, синтетический libretro
callback, независимые повторы и отказ при попытке включить
в отчёт исходные пиксели/RAW RAM.

## Что это НЕ подтверждает

- Отдельный синий компонент может быть фоном, а не Дональдом.
- В анимации синяя одежда персонажа может разбиваться на несколько
  фрагментов: самую крупную компоненту нельзя автоматически считать
  полным спрайтом.
- Сканирование цвета не определяет hitbox, точку опоры ног,
  тайловые коллизии или смещение между RAM Y и реальной поверхностью.
- Успешный CI с искусственными данными не равнозначен новому запуску
  оригинальной игры.

Поля `safe_to_modify_switch_physics` и подтверждения исходного
хитбокса остаются `false`. Код C99 и Switch NRO не изменяются.
