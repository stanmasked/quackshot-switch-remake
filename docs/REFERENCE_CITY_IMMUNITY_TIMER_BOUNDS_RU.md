# QuackShot Remake — этап №51: границы неуязвимости и оглушения

## Проблема

В исследовательском CITY TEST таймер неуязвимости героя
`hero.hurt_frames` мог содержать повреждённое отрицательное значение,
которое трактовалось как ненулевое и уменьшалось дальше. Например,
`-1` делал героя неуязвимым неопределённо долго, а `INT_MIN` мог
вызвать переполнение знакового целого. Чрезмерно большой положительный
таймер `INT_MAX` также давал практически бесконечную защиту.

Аналогично у противников отрицательный счётчик оглушения уже
нормализовывался предыдущим этапом, но крайне большие положительные
значения оставались без верхней границы.

## Реализация

- Только при `QS_PHYSICS_REFERENCE_CITY` на CITY TEST до проверки
  столкновений отрицательный `hero.hurt_frames` заменяется нулём:
  повреждённый таймер не создаёт неуязвимость.
- Значение выше 90 ограничивается 90 кадрами. Обычное попадание задаёт
  70 кадров, повторное появление — 90; допустимые значения не меняются.
- Для `enemies[i].stunned_frames` отрицательное значение становится 0,
  а превышающее 180 ограничивается 180. Корректные таймеры сохранены.
- Существующий порядок остаётся прежним: последнее защищённое состояние
  со счётчиком 1 **блокирует** столкновение в текущем кадре, затем
  таймер становится 0. Урон возможен только на следующем кадре.
- В случае одновременных противников неуязвимость не пропускает второй
  урон в том же тике; смертельная гибель вызывает одно возрождение.
- Обычный профиль прототипа **не изменяется**.

Это технические ограничения собственного движка, а не восстановленные
таймеры или исходные инструкции оригинального QuackShot.

## Тесты

Файл `tests/test_reference_city_timer_bounds.c` содержит 14 сценариев:
отрицательные таймеры, `INT_MIN`, `INT_MAX`, значения непосредственно
выше границы, нормальные периоды 70 и 90, последний безопасный кадр,
точное пробуждение врага, смешанные одновременные контакты, один
смертельный повторный запуск, изоляция базового профиля и
600-кадровый детерминированный прогон с намеренно повреждёнными
значениями.

`TIMER_BOUNDARY_SDL_PASS` проверяет **фактический растр SDL2**:
третий индикатор сердца остаётся красным в последнем защищённом
кадре, а после истечения неуязвимости и контакта с противником
становится тёмным. Отдельный пиксель подтверждает, что корректно
ограниченный оглушённый противник остаётся видимым.

Предусмотрены GCC/Clang Debug/Release, SDL2, Switch NRO и гостевой
запуск в NeXium. Их прохождение следует подтверждать по
GitHub Actions итогового коммита. Полноценный ремейк и проверки
на физической Nintendo Switch пока не заявляются.

В репозитории нет оригинальных игровых спрайтов, музыки или ROM.
