# QuackShot Remake — Stage196: неоднозначность оригинальной координаты Y

## Причина

Stage195 закрепляет **геометрию нашего самостоятельного тестового движка**:
прямоугольник героя 12×20, `hero.y` — верх, контакт с полом —
`hero.y + 20`. Для авторского 32px уступа поверхности лежат на
Y=176 и Y=208, а верх персонажа при устойчивой опоре на Y=156 и Y=188.

Однако ранее опубликованные **числовые измерения оригинала** содержат
изменение Y с 176 на 208 без независимого доказательства, является ли
RAM Y ногой, центром, верхом, точкой привязки спрайта или ещё одним
адресуемым положением.

## Математический результат

Пусть наблюдения оригинальной RAM равны `y0=176`, `y1=208`, а
постоянный сдвиг между оригинальной RAM координатой и координатой
верхней границы **гипотетического** прямоугольника равен `c`.

```
transformed_y0 = y0 + c
transformed_y1 = y1 + c
transformed_y1 - transformed_y0 = y1 - y0 = 32
```

Следовательно, два наблюдения с разницей в 32 пикселя **не определяют
сдвиг `c`**. Для иллюстрации применены три разных константы, привязанные
**только к размерам нашего авторского прямоугольника**:

| Гипотетический сдвиг | Верхняя метка | Нижняя метка | Разность |
|---|---:|---:|---:|
| `c = 0` | 176 | 208 | 32 |
| `c = -10` | 166 | 198 | 32 |
| `c = -20` | 156 | 188 | 32 |

Совпадение строки `c = -20` с нашей авторской координатой верха
**не подтверждает**, что оригинальная RAM Y — это координата ноги
20-пиксельного персонажа. В оригинале неизвестны размер хитбокса,
опорная точка, смещение камеры и момент геометрического контакта.

## ROM-free инструмент

`tools/city_y_anchor_identifiability.py` извлекает ранее опубликованные
числовые координаты через существующий аудит `reference_evidence_integrity`.
Он также статически сверяет авторское использование
`hits_tiles(...,12,20)` и правила посадки `top=surface-20`
в `src/qs_game.c`, чтобы смысл демонстрации не устарел после
изменений в коде.

```sh
python3 tools/city_y_anchor_identifiability.py --out /tmp/city-y-ambiguity.json
python3 -m unittest discover -s tests -p 'test_city_y_anchor_identifiability.py' -v
```

Отчёт фиксирует `status=UNDERDETERMINED_BY_PUBLISHED_NUMERIC_Y_ONLY`,
`original_anchor_selected=null` и
`safe_to_modify_switch_physics=false`. Три сдвига — **гипотезы, а не
измерения оригинальной геометрии**. Тесты отвергают изменение опубликованных
числовых наблюдений и дрейф размеров нашего собственного хитбокса.

## Следующий проверяемый шаг

Нужно независимое приватное свидетельство о значении оригинальной RAM Y:
например, измеренная физическая точка контакта при неподвижном персонаже
и смене этажей плюс привязка к границе столкновения. Только такое
свидетельство может отделить возможный числовой сдвиг от подлинной
разницы во времени падения.

Этот этап **не запускает оригинальный ROM**, не содержит спрайтов,
RAW RAM, видео, аудио и BK2. Switch-физика, карта и NRO не меняются.
