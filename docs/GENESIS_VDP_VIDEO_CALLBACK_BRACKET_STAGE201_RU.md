# QuackShot Remake — Stage201: проверка VDP внутри видеоколбэка и после кадра

## Задача

Stage200 научился сопоставлять RAM Y, синюю область изображения
и аппаратный VDP на **одном индексе вызова libretro**. Но
`video_refresh` вызывается **во время** `retro_run`, а RAM и
HScroll читаются **после** возвращения `retro_run`.
Это разные точки наблюдения. Они могут совпадать численно или нет;
ни один вариант сам по себе не доказывает фазу VBlank и положение
спрайта на физическом дисплее Mega Drive.

Stage201 добавляет необязательный и строго ограниченный механизм
съёма **8 целых чисел аппаратного HScroll** непосредственно внутри
временного callback видеокадра: по Plane A и Plane B на линиях
0, 64, 128 и 192. Сырые VRAM, RAM и framebuffer из callback не
выводятся.

## Что реализовано

- `tools/genesis_libretro_probe.py` принимает новый необязательный
  `video_roi_vdp_hook`. Он допускается только с указанным `video_roi`,
  вызывается на каждом выбранном видеоиндексе и обязан вернуть ровно
  8 целых чисел из диапазона от −1024 до 1023. Любая попытка вернуть
  байты, словарь, лишнее поле, нецелое число либо недостающий шаг
  ведёт к отказу.
- `tools/genesis_city_video_vdp_bracket_probe.py` читает эти же
  VDP-регистры повторно после `retro_run` через существующий
  read-only исследовательский hook специальной сборки
  Genesis Plus GX.
- Каждая из 5 контрольных точек (2180, 2220, 2280, 2297, 2350)
  получает 8 разностей: `post_run - video_callback`.
  Отличие хотя бы одной из них означает
  **VDP-значение изменилось между точками наблюдения**.
- Проводятся независимые idle, RIGHT, RIGHT-repeat прогоны,
  проверяются их воспроизводимость, входные SHA-256 ROM и
  инструментированного ядра, известные целочисленные позиции,
  корректность VDP и целостность входных файлов до/после каждого
  запуска.

Значения, одинаковые на обеих границах, подтверждают **только
равенство отсчётов HScroll**. Они не доказывают, что CPU, VDP,
вывод scanline или логика столкновения полностью синхронны.

## ROM-free тестирование

```sh
python3 -m unittest discover -s tests \
  -p 'test_genesis_city_video_vdp_bracket_probe.py' -v
```

Искусственное libretro-ядро позволяет проверить вызов
`video_roi_vdp_hook` **внутри callback**, разницу двух отсчётов,
потерю кадра, двойной callback, неправильные данные, ошибку
целостности и отсутствие данных исходной игры в выходном отчёте.

## Приватный запуск при наличии локальных исходных файлов

```sh
python3 tools/genesis_city_video_vdp_bracket_probe.py \
  --rom "/private/QuackShot Starring Donald Duck.gen" \
  --core "/private/genesis_plus_gx_instrumented_libretro.so" \
  --roi 100 80 85 140 \
  --output "/private/quackshot-hscroll-bracket-stage201.json"
```

Два SHA-256 фиксированы: исходный ROM
`30581220f6c914709853828811fe143e283896189a64eedf1444dc908b5cac34`,
специальное VDP-ядро
`4e3381cf5bfa7ff387bbe6887e7e31453bf4c8c85b295aa66d6d07d415dde7aa`.

Отчёт сохраняется исключительно новым приватным JSON вне git,
с правами 0600, без перезаписи существующих файлов.
Оригинальный ROM в рамках Stage201 **не выполнялся**.
Анализатор не меняет игровой код C99, NRO, физику и контент Switch.

## Ограничение

Вызов исследовательского VDP hook из видеоколбэка — отдельная
экспериментальная точка наблюдения и должен проверяться в настоящей
приватной эмуляции. Даже результат с совпадающими числовыми
отсчётами не подтверждает реальную границу столкновения героя
или точное время аппаратного scanout.
