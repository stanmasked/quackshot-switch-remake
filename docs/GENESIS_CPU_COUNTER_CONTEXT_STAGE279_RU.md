# QuackShot Remake — Stage279: контекст ветвления счётчика объекта

## Цель

Stage278 показал повторяемый 16-шаговый счётчик по адресу `0xFFA2E6`, который запускается в определённых путях прыжка. Приватная трасса PC/CCR уточнила: счётчик инициализируется через `$26(A0)`, уменьшается на каждой итерации, а при нуле выполняется отдельный путь, сбрасывающий байт объекта по `$08(A0)`. При `A0=0xFFA2C0` это `0xFFA2C8`.

## Изменения в этой ветке

- В CPU PC allowlist добавлен узкий диапазон `[0x64D0, 0x6560)`, охватывающий инициализацию, декремент, проверку нуля и переходный путь.
- В CPU read allowlist добавлен однобайтный диапазон `[0xEE03, 0xEE04)`, чтобы фиксировать числовое чтение до операции над глобальным байтом.
- Обновлены C hook и Python-контракт диапазонов, тесты и синтетические assertions в Genesis libretro workflow.
- В отчёты по-прежнему включаются только числовые события; исходный ROM, сырые дампы RAM/VRAM, байты инструкций, пиксели и аудио не экспортируются.

## Наблюдение, требующее дальнейшего подтверждения

На исходном образе PC `0x64E4` записывает `0x10` в `$26(A0)`; PC `0x6540` выполняет `SUBQ.W #1,$26(A0)`; PC `0x6544` ветвится на `0x6558`, пока результат ненулевой. При нуле путь проходит через `0x6546`, `0x6548`, `0x654C`, `0x6552`, затем возвращается к `0x6558`. На `0x6552` байт `$08(A0)` сбрасывается в ноль, а на следующем кадре снова проходит значения 0 и 1.

Это связывает счётчик с переходом состояния/анимации, но его точное игровое значение не установлено. Счётчик отсутствует, когда горизонтальное направление удерживается во время прыжка, поэтому его нельзя считать универсальным таймером приземления.

## Приёмка

1. Python unit tests подтверждают точные read/PC allowlists.
2. Genesis libretro workflow компилирует HOOK_CPU=1 core.
3. Синтетический тест подтверждает прежнюю пару write/read на `0xFFA2E6`, а отчёт содержит новые диапазоны и нулевое переполнение.
4. Приватный оригинальный ROM остаётся только в owner-only Google Drive; CI не получает его.
