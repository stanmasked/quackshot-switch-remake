# QuackShot Remake — Stage198: числовой анализ видимой области Genesis

## Цель

Stage195 подтвердил геометрию **нашего** тестового героя: координата
`hero.y` — верх тела 12×20. Stage196 показал, что известные RAM Y=176
и Y=208 оригинальной игры не определяют, где находится её hitbox.

В предыдущих приватных исследованиях рассматривалась средняя X-координата
пикселей синего оттенка спрайта Дональда. Stage198 добавляет
**воспроизводимый числовой алгоритм** для произвольно выбранной маленькой
области кадра (ROI). Он не даёт гарантий, что голубые пиксели
принадлежат именно игроку, и **не** определяет коллизионную поверхность.

## Обработка только в памяти

Новый `tools/genesis_blue_roi_numeric.py` принимает временные кадры
libretro в форматах:
- `0RGB1555` — формат 0;
- `XRGB8888` — формат 1;
- `RGB565` — формат 2.

Каждый пиксель нормализуется до пятибитных компонент RGB. Авторский,
не извлечённый из оригинальной палитры фильтр отмечает пиксель, если
`B >= 19`, `B-R >= 8`, `B-G >= 4`. Классификация приблизительная,
а не проверенный детектор силуэта.

Возвращаются **только числа**:
- заданная ROI и формат;
- количество подходящих пикселей;
- центроид X/Y, умноженный на 1000, целочисленный;
- исключительная граница `[xmin, ymin, xmax, ymax]`;
- `source_collision_plane_measured=false`.

Для пустого совпадения центроид и рамка равны `null`; это **не**
свидетельство, что игрока на кадре нет.

## Подключение к локальному libretro

`tools/genesis_libretro_probe.py` теперь допускает необязательные
именованные аргументы `video_roi` и `video_roi_frames` в
`run_core(...)`. До вызова ядра проверяется:

1. ROI — четыре строго целых числа с положительными размерами;
2. ровно 1–24 уникальных кадров для выборки, внутри диапазона исполнения;
3. ROI полностью содержится в кадровой области;
4. корректны шаг строки, буфер кадра и формат пикселей;
5. по каждому заданному кадру получен ровно один корректный числовой
   результат (пропуск, дубль или ошибочный callback запрещён).

Видео обрабатывается только во время закрытого callback.
Отдельные исходные изображения, байты RGB, аудио, ROM, RAW RAM и
кадровые массивы в возвращаемом отчёте не появляются. По умолчанию
`video_roi=None`, поэтому старые пробники и их результат без изменений.

## Проверки

```sh
python3 -m unittest discover -s tests -p 'test_genesis_visual_roi_numeric.py' -v
```

ROM-free тесты используют **выдуманные цветные пиксели** в трёх
форматах, проверяют одинаковый центроид при разных кодировках,
нулевые совпадения, отбрасывание белого/зелёного/голубого, повреждённый
pitch/буфер, выход ROI за экран и неверный список кадров.

## Следующий шаг

Чтобы получить настоящее числовое свидетельство о визуальном
положении Дональда, понадобится локально выполнить pinned Genesis Plus GX
с пользовательским ROM и заранее ограниченной ROI. Значения нужно
сопоставить с исходной RAM Y на одних и тех же кадрах и подтвердить
детектор пикселей дополнительным независимым способом.

Даже при таком измерении **положение нарисованного спрайта и
коллизионная граница не равнозначны**. Stage198 не запускает ROM,
не меняет физику Switch и не подтверждает оригинальную hitbox.
