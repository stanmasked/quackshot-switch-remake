# QuackShot Remake — Stage189: безопасное сравнение дробного Y с CITY TEST

## Задача

Stage186 и Stage187 подтвердили, что для нашего самостоятельно созданного 32-пиксельного уступа при регистрации Y>0,01px получается 17 кадров падения, при пороге Y>0,25px — 16, при Y>1px — 15. В ранее опубликованных **оригинальных** числах первый целый Y=177 отмечен на кадре 2281, достижение целого Y=208 — на кадре 2297, то есть разность целочисленных меток равна 16 кадрам.

Эти величины нельзя без уточнения сравнивать между собой: начало **любого** положительного дробного изменения Y — это порог Y>0, а не Y>0,01px, и оригинальная целая координата может иметь другой геометрический смысл, чем Y нашего героя.

На Stage188 создан локальный read-only Genesis Plus GX инструмент для измерения дробных порогов. Stage189 добавляет **проверку и сравнительный отчёт**, который не позволяет ошибочно объявить результаты ROM-free теста подтверждённым оригинальным прохождением.

## Новый инструмент

`tools/city_fractional_witness_comparison.py` работает в двух режимах.

**Без нового числового свидетельства:** сверяет уже опубликованные оригинальные целочисленные ориентиры, а при наличии JSON Stage186 выводит синтетические длительности 17/16/15. Возвращает статус `NO_NEW_ORIGINAL_FRACTIONAL_MEASUREMENTS` и **null** для неизвестных оригинальных дробных длительностей. Никаких предположительных чисел не заполняет.

**С числовым Stage188 JSON:** проверяет точную схему, SHA-256 исходного пользовательского ROM, хеш уже документированного Genesis Plus GX, три независимых запуска, согласованность абсолютных и относительных временных меток, полноту и хронологию порогов. Запрещает незаявленные поля с массивами памяти/кадров. Сопоставляет **только одинаково определённые пороги >0,25px и >1px**. Порог >0px оригинала и >0,01px нашей модели сохраняются отдельно и не сравниваются друг с другом как тождественные.

Важно: даже корректно оформленный внешний JSON **не является криптографическим подтверждением** факта приватной эмуляции. Поэтому статус отчёта с ним — `USER_NUMERIC_WITNESS_NOT_INDEPENDENTLY_ATTESTED`; его значения остаются предоставленным извне числовым свидетельством, а не результатом запуска, выполненного Stage189.

## Использование

Без нового оригинального измерения:

```sh
python3 tools/city_fractional_witness_comparison.py --out /tmp/fractional-baseline.json
```

Со свежими синтетическими числами после запуска Stage186:

```sh
python3 tools/city_fractional_witness_comparison.py \
  --synthetic-report /tmp/city-drop-height.json \
  --out /tmp/fractional-baseline.json
```

Когда локальный пробник Stage188 **реально** выполнился на пользовательском приватном ROM, на том же доверенном компьютере можно сравнить его числовой итог:

```sh
python3 tools/city_fractional_witness_comparison.py \
  --synthetic-report /tmp/city-drop-height.json \
  --fractional-witness /private/quackshot-fractional-fall-numeric.json \
  --out /private/fractional-comparison.json
```

Ни один из этих режимов не запускает ROM, не читает его содержимое и не записывает дампы RAM. Исходный Stage188 JSON следует хранить вне публичного GitHub.

## Автоматический контроль

Девять независимых Python unit tests с **искусственными** данными проверяют: отсутствие выдуманных оригинальных меток, согласованные одноимённые пороги, отказ от неопознанных полей, несовпадающего SHA ROM/core, ложного флага оригинального запуска, повреждённой последовательности событий, несогласованных числовых интервалов, неверного синтетического отчёта и несогласованных публикаций.

- В `Genesis motion repeatability` тест запускается без оригинального ROM; контрольный отчёт обязан показывать отсутствие нового измерения.
- В `Portable gameplay core` четыре сборки GCC/Clang дополнительно анализируют **настоящий синтетический** JSON Stage186 из соответствующей сборки, публикуют `city-fractional-baseline.json` и проверяют одинаковые результаты всех четырёх конфигураций.
- Игровое ядро C99, сцены, физика, графика и Nintendo Switch NRO **не изменяются**. Публикуются только собственные программы, тесты и отчёт без защищённого контента.

## Ограничение

Пока отдельное реальное измерение дробной части оригинальной координаты Y не проведено, расхождение 17 против 16 кадров **остаётся неопределённым**: оно может объясняться порогом, фазой чтения RAM, правилами коллизии или различием геометрии. Этот этап не выбирает удобный порог для искусственной подгонки и не меняет гравитацию ради совпадения одной временной метки.
