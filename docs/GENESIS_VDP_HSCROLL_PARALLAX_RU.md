# Этап №17 — аппаратная таблица HScroll оригинальной Mega Drive

**Подтверждённое новое свидетельство.** Использован только приватный
пользовательский QuackShot ROM 524288 байт, SHA-256:
30581220f6c914709853828811fe143e283896189a64eedf1444dc908b5cac34.

Исходный ROM, изображения, VRAM/оперативная память, музыка и
сохранённые состояния **не загружались** в GitHub и не входят в NRO.

## Два различных уровня наблюдений

1. Ранее исследованный RAM 0x8524 — программный кандидат на
   **горизонтальную позицию камеры**. Именно он фиксирует
   границы слежения около 141 пикселя вправо и 123 влево.
2. Новое поле RAM **0x852C** связано непосредственно с таблицей
   **HScroll видеопроцессора**. Оно чуть запаздывает за 0x8524
   в переходных кадрах, но его значение точно совпадает с
   числовыми величинами аппаратной прокрутки.

Для подтверждения второго факта было недостаточно читать
64 КиБ системной RAM: интерфейс libretro не предоставляет
полный VDP VRAM напрямую. Поэтому из **зафиксированного
открытого исходника Genesis Plus GX** собрана ROM-free
исследовательская библиотека с отдельной числовой функцией
quackshot_research_vdp_hscroll().

Она читает только регистры VDP 11/13, базовый адрес HScroll,
режим индексации и **два 16-битных числовых слова** из
соответствующей аппаратной таблицы VRAM. Исходные
VRAM-байты, тайлы, спрайты и палитры не экспортируются.
Инструмент и патч НЕ включаются в сборку Switch.

## Аппаратная конфигурация исследованной сцены

При успешном входе в первую игровую городскую сцену:

| Поле VDP | Подтверждённое значение |
| --- | --- |
| Регистр 11: режим HScroll | 0 — одна позиция для всех строк |
| Регистр 13: адрес таблицы | 52 (0x34) |
| База HScroll в VRAM | **0xD000** |
| Маска индексации строк | 0 |
| Выборка строк | 0, 64, 128, 192 |

При маске 0 все четыре исследованные строки используют
одну и ту же запись таблицы, что подтверждено
каждым из 1910 покадровых наблюдений.

## Точная связь двух плоскостей с RAM

Пусть S — значение 16-битного слова в игровой RAM по
смещению **0x852C**, прочитанное как unsigned little-endian.

На всех проверенных наблюдениях:

    HScroll_plane_A = -S
    HScroll_plane_B = -floor(S / 2)

Это проверено по 382 кадрам каждого из 5 независимых
оригинальных запусков, на 4 скан-строках, по обеим
плоскостям: **1910 × 4 × 2 = 15280
точных числовых сопоставлений, ноль расхождений**.

| Кадр | Программная камера 0x8524 | Буфер 0x852C | VDP A | VDP B |
| --- | ---: | ---: | ---: | ---: |
| 2069 | 0 | 0 | 0 | 0 |
| 2180 | 92 | 90 | −90 | −45 |
| 2220 | 157 | 155 | −155 | −77 |
| 2300 | 287 | 285 | −285 | −142 |
| 2400 | 358 | 358 | −358 | −179 |

В результате установлен **параллакс 2:1**: фон на
плоскости B прокручивается вдвое медленнее плоскости A.
Отрицательный знак — соглашение аппаратной горизонтальной
прокрутки относительно положительного сдвига камеры.

## Разворот: RAM 0x8524 опережает фактическую VDP-прокрутку

После остановки в мировой X=498 у преграды:

| Кадр | Мир X | 0x8524 | 0x852C | VDP A | VDP B |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2360 | 498 | 358 | 358 | −358 | −179 |
| 2375 | 480 | 357 | 358 | −358 | −179 |
| 2380 | 472 | 349 | 351 | −351 | −175 |
| 2390 | 455 | 333 | 335 | −335 | −167 |
| 2430 | 397 | 273 | 273 | −273 | −136 |

Таким образом, **состояние камеры и фактически отрисованный
сдвиг нельзя отождествлять на переходных кадрах**.
Нельзя также считать адрес 0xFEC6 точной копией 0x8524:
обнаружены отдельные кадры с другими значениями.

## Порядок воспроизведения

Сборку свободного Genesis Plus GX выполняет
.github/workflows/genesis-libretro-core.yml без доступа
к пользовательскому ROM. Используется исходный коммит
aa74d79634cd230f65cce4180e92688e53883d2f и
вспомогательный файл tools/genesis_vdp_hscroll_export.c.
В разрешённые символы исследовательской сборки добавлено
только новое числовое API. Лицензия эмулятора содержит
ограничения некоммерческого использования.

После скачивания артефакта ROM-free локально:

    python3 tools/genesis_vdp_scroll_probe.py \
      --core /private/genesis_plus_gx_libretro.so \
      --rom "/private/QuackShot Starring Donald Duck.gen" \
      --expected-sha256 30581220f6c914709853828811fe143e283896189a64eedf1444dc908b5cac34 \
      --output /tmp/quackshot-actual-vdp-hscroll.json

Инструмент проверяет контрольные прогоны, число кадров,
поступление нажатий, совпадение каждого значения VDP
с RAM 0x852C и возвращает только числовое свидетельство.

Опубликованные проверенные числа:
research/observations/user_rom_vdp_hscroll_2026-10-18.json.

## Границы результата

Измерены числовые значения **внутреннего эмулируемого
видеопроцессора после каждого кадра**, а не трасса
конкретных инструкций 68000, выполнявших VRAM-записи.
Для этой одной городской сцены установлен полноэкранный
режим HScroll и параллакс 2:1. Нельзя обобщать результат
на все локации, построчный HScroll, интерлейс и анимации
без дополнительных запусков.

В Switch-прототипе по-прежнему применяются
самостоятельные тестовые карты. Для повторения параллакса
в будущем понадобится *оригинальная структура слоёв*,
но оригинальные изображения и карты при этом не
должны автоматически попадать в распространяемую сборку.
